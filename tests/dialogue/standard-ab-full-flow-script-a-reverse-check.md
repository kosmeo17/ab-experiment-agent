# 剧本 A 反向压测记录

## 目的

验证 `standard-ab-full-flow-script-a.md` 不只是对话看起来顺，而是每个关键用户输入都会把 `$ab-experiment-agent` 推到正确的下一阶段。

## 关键断点

### 断点 1：场景确认后

- 输入轮次：第 8 轮
- 用户输入：聊天翻译次数用完后弹出来的 Paywall
- 应进入阶段：新增数据需求 / 数据支持
- 必须避免：直接问分组、直接查流量、直接查基线、直接问灰度
- 当前结果：通过

### 断点 2：数据支持确认后

- 输入轮次：第 10 轮
- 用户输入：数据同学说这个入口能圈到，不需要新增数据需求
- 应进入阶段：分组设计
- 必须避免：继续追问数据支持、直接查样本量、直接问互斥
- 当前结果：通过

### 断点 3：分组确认后

- 输入轮次：第 12 轮
- 用户输入：是
- 应进入阶段：互斥关系
- 必须避免：直接问灰度比例、直接查流量、直接生成草稿
- 当前结果：通过

### 断点 4：用户不知道灰度时

- 输入轮次：第 14 轮
- 用户输入：我不知道，灰度也不知道怎么定
- 应进入阶段：样本量 / 灰度判断，允许路由 `$da-agents` 查触发流量、基线、历史波动或样本量输入
- 必须避免：让用户拍脑袋给灰度比例、回退到必要性、生成正式草稿
- 当前结果：通过

## 结论

剧本 A 当前通过反向压测。核心状态机为：

`必要性 -> 指标 -> 实验对象 -> 触发场景 -> 新增数据需求 -> 分组设计 -> 互斥关系 -> 样本量/灰度 -> 待补齐骨架或正式文档`

样本量 / 灰度阶段的 `$da-agents` 路由只在用户不知道灰度或需要真实输入时出现，不再由触发场景确认自动触发。
