# 依赖能力版本检查

当 AB 实验任务需要调用 `$cms`、`$da-agents`、飞书 / Lark、UI / PRD 类外部能力，并且结论依赖最新配置结构、最新指标库、最新标签库、最新事件定义、最新本地 agent 行为或生产配置时，使用本参考。

## 核心原则

AB skill 不能假设自己打包时附带的外部能力就是最新版本。它应该提醒 owner 先检查依赖能力是否需要更新；只有 owner 确认或当前任务低风险时，才继续按当前本地版本执行。

版本提醒不是授权自动更新：

- 可以检查：本地是否存在依赖、当前版本 / commit、远端是否可能有更新。
- 可以提示：`检测到依赖能力可能不是最新版本，要不要先更新？`
- 不得静默更新 `$cms`、`$da-agents`、飞书 CLI、UI/PRD agent 或其他外部工具。
- 不得把“已安装”写成“最新”。只有实际检查远端或官方版本后，才能说“当前已是最新”。

## 什么时候必须提醒

出现以下情况，先提醒或建议检查版本：

- 需要读取 CMS 最新配置、用户标签、推送系统结构、ABTest 指标树或服务开关。
- 需要 `$da-agents` 查真实数据、事件定义、样本量输入或实验复盘结果。
- 用户问“现在系统里有没有”“最新配置是什么”“标签是否存在”“指标库有没有”“这个 agent 能不能查”。
- 最近刚反馈过某个外部 agent 能力变更、接口变更或规则不一致。
- 正式结论会影响飞书正式文档、配置上线、生产变更、样本量 / 灰度判断或对外协作。

低风险的普通思路引导、非正式草稿、纯结构评审，不需要每轮打断式提醒；可以在进入真实读取前提醒。

## 面向 owner 的默认话术

简短说清楚即可：

```text
这一步要用到本地 $cms / CMS-CLI 读取最新标签和配置。这个能力可能独立更新；建议先检查一下是否有新版本。你要我先检查更新状态，还是直接按当前本地版本只读查询？
```

如果当前环境已经检查过：

```text
我已检查：$cms 当前可用，但未确认远端是否最新。下面先按当前本地版本只读查询；如果查不到，再回到版本 / 权限检查。
```

## 安装脚本边界

`install.sh` 可以做这些事：

- 更新 `ab-experiment-agent` 自身。
- 复制随包携带的 bundled skills。
- 检查 `lark-cli`、`cms-cli`、`DA_AGENTS_HOME` 是否存在。
- 对本地 git 仓库做远端 commit 差异检查，并提示是否可能需要更新。
- 通过 `AB_EXPERIMENT_AGENT_REPO_URL` 指向私有 GitLab / GitHub 发布源。
- 通过本机 git 凭据或临时 `AB_EXPERIMENT_AGENT_GIT_TOKEN` 完成私有仓库安装 / 更新。

`install.sh` 不应该：

- 自动更新 DA 项目、CMS-CLI、lark-cli 或其他外部 agent。
- 把 token 写进仓库、日志或 README。
- 把 token 写进 git remote URL、反馈表、commit message 或回复正文。
- 在没有用户确认时写入、发布或修改生产配置。

## 输出边界

版本检查结果只能作为环境状态，不是业务事实。即使依赖已是最新，标签、指标、事件、流量和基线仍需要按对应 CMS / DA 只读流程实际读取后才能写成确认结果。

反馈、发布和安装更新闭环按 `references/feedback-maintenance.md` 执行。反馈表只用于维护记录，不等于最新 CMS / DA / 指标 / 标签事实来源。
