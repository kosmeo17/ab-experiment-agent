# 反馈与维护闭环

当 owner 或数据 / 产品 / 开发同事反馈 AB 实验助手规则问题、输出问题、缺少知识源、外部 agent 版本问题或安装更新问题时，使用本参考。

## 边界

反馈表是维护数据库，不是 AB 实验业务数据源。

- 可以记录：反馈原文、截图 / 链接、影响范围、处理状态、修复版本、验证用例、发布状态。
- 可以读取：已有反馈表记录，用于判断是否有重复问题、历史处理结论或待验证事项。
- 不得把反馈表里的业务判断当成指标、标签、样本量、配置或实验结论的事实来源。
- 不得在未获明确授权时创建飞书多维表格、添加机器人、发送通知、改表结构或写入记录。
- 不得把 GitLab 临时 token、飞书 token、机器人 webhook、cookie、session 或任何密钥写入反馈表、README、日志、commit message 或对话输出。

## 推荐多维表格字段

如果 owner 授权创建或维护飞书多维表格，建议把每条反馈作为一条记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| feedback_id | 文本 | 稳定编号，例如 `ABAG-20260804-001`。 |
| created_at | 日期时间 | 反馈进入表的时间。 |
| source | 单选 / 文本 | 来源，如数据同事、运营、产品、开发、Codex 对话、飞书评论。 |
| source_link | 链接 | 飞书消息、文档、截图、GitLab issue 或本地路径。 |
| feedback_text | 长文本 | 反馈原文，保留对方表达。 |
| category | 单选 | 指标、用户标签、外部 agent、安装更新、飞书文档、兼容性、其他。 |
| severity | 单选 | P0 / P1 / P2 / P3。按是否影响正式结论、生产配置、数据读取或交付可信度判断。 |
| affected_scope | 多选 / 文本 | 影响的规则、参考文件、脚本、安装方式或平台。 |
| expected_behavior | 长文本 | 修复后应该怎么表现。 |
| actual_behavior | 长文本 | 当前错误或缺口。 |
| status | 单选 | 新增、已确认、处理中、待验证、已发布、暂不处理、关闭。 |
| owner | 人员 | 当前处理人。 |
| target_version | 文本 | 计划发布版本或 commit。 |
| fix_commit | 文本 / 链接 | 实际修复 commit 或 MR / PR。 |
| verification_case | 文本 | 对应 acceptance case / regression checklist 编号。 |
| release_status | 单选 | 未发布、已合入未安装、已安装未验证、已验证。 |
| notes | 长文本 | 处理说明、取舍、残余风险。 |

## 状态流转

默认状态流转：

1. `新增`: 只记录原始反馈，不先改规则。
2. `已确认`: 已判断反馈是否有效、影响范围和能否实现。
3. `处理中`: 正在修改规则、脚本、文档或测试。
4. `待验证`: 已完成本地修改，等待回归或 owner 验收。
5. `已发布`: 已同步到安装源或远端发布源。
6. `关闭`: owner 确认问题解决，或明确暂不处理。

如果反馈涉及生产写入、密钥、机器人通知或外部系统配置，状态只能推进到`已确认`，必须等 owner 明确授权后才能执行写操作。

## 机器人通知

飞书机器人只用于提醒维护者有新增记录或状态变化，不用于自动修改 skill。

推荐通知触发：

- 新增反馈记录。
- `severity` 为 P0 / P1。
- `status` 进入 `待验证`。
- `release_status` 进入 `已发布` 或 `已验证`。

通知内容只包含反馈编号、标题 / 摘要、状态、负责人和表格链接。不要发送 token、完整隐私内容、用户个人信息或内部查询结果。

## 更新安装

AB 实验助手自身可以通过 GitLab / GitHub 远端更新，但安装脚本必须遵守：

- 支持通过 `AB_EXPERIMENT_AGENT_REPO_URL` 指定仓库地址。
- 私有 GitLab 临时 token 只能通过环境变量或本机凭据临时提供。
- 不把 token 写进 git remote、README、表格、日志或输出。
- 检测到远端有更新时，只提示 owner 是否更新；除非用户正在运行安装 / 更新脚本，否则 agent 不应静默拉取。
- 外部依赖如 `$cms`、`$da-agents`、lark-cli、cms-cli 仍按 `references/dependency-version-checks.md` 单独检查，不随 AB agent 自动更新。

## 处理反馈时的回答模板

```text
这条反馈我会这样处理：

- 能不能实现：可以 / 部分可以 / 暂时不能。
- 影响范围：会改哪些规则、脚本或输出结构。
- 不会做的事：不会创建外部表格 / 不会写入生产 / 不会保存 token，除非你明确授权。
- 下一步：先登记为反馈记录，再修改本地规则，并补一条回归用例验证不会回退。
```
