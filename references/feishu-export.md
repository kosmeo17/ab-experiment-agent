# 飞书/Lark 文档工作流

当用户要求读取、创建、更新、导出或准备飞书/Lark 云文档里的 AB 实验方案时，使用本参考。

## 内容与状态边界

飞书/Lark 是 AB 实验方案、SOP 和案例的文档渠道，不是数据平台。读取飞书文档可以获得来源文本，但不能证明 Doris、TA、DA、看板、事件或指标支持已经检查过。

- 用户明确要求创建或更新飞书/Lark 文档，且工具与授权可用时，直接执行文档动作。
- 方案字段完整且证据达到正式门槛时，写`正式方案`。
- 任一设计或证据字段未完成时，写`待补齐版`；不得因字段缺失拒绝已明确提出的文档创建/更新请求。
- `待补齐版`可以交接和继续讨论，但不能写成`已验证`、`已定稿`、`可进入配置准备`或已可上线。
- 只有正式方案才受完整 Gate 约束：必要性、已确认的核心指标/过程指标/护栏指标、对象、场景、数据支持、分组、互斥、样本量与灰度证据必须闭合。

不要用精美文档格式掩盖缺口。缺口应在对应位置使用统一的`待确认：`或`待补充：`明确标出；不要编造事实、默认写`无`，也不要写`无需新增数据支持`或`互斥：无`，除非该事实已由 owner 或来源确认。

## 文档标题与章节

- 除非用户明确要求其他命名方式，标题使用`AB实验 | xxxx`。
- `待补齐版`在标题末尾标识，例如`AB实验 | 曝光用户召回实验（待补齐版）`。
- 标题禁止出现`agent生成`、`AI生成`、`自动生成`、`助手生成`或同类过程标识。

默认章节：

1. 背景与必要性
2. 评估指标
3. 实验对象
4. 实验场景
5. 数据支持
6. 互斥和灰度比例
7. 具体分组说明
8. 样本量设置
9. 上线前检查、实验过程中的复盘与提醒
10. 来源与附件

不要额外输出`实验概览`、`实验假设`、`唯一变量`、`分组字典`、`用途`、`业务域与 AI 推断`或配置交接章节。内部判断或配置内容只有在用户明确要求配置/上线准备时，才通过相应交接输出，不进入这份业务文档。

## 业务正文边界

飞书正文面向业务读者，只写事实、结论、业务可读定义和待确认项：

- `评估指标`固定包含核心指标、过程指标和护栏指标。过程指标可由 agent 推荐，但必须经 owner 确认；未确认时写`待确认：过程指标`，不得默认写`无`。护栏只能有一项，也必须经 owner 确认。
- 指标用中文名称和简短业务口径展示。不得展示 key、事件名、字段名、标准库映射状态、owner 确认状态、AI 状态、承载系统、服务开关、配置路径或任何系统/配置细节。
- `实验对象`只写谁有资格进入实验；`实验场景`只写这些用户在什么行为或位置受到策略影响。两者不得混写，也不得补造入口、页面、点击或事件。
- `数据支持`只写已确认支持的范围，或写`待确认：是否已有场景、对象和指标数据支持`。需要新增时写明确新增项；不确定时不能断言无需新增。
- `互斥和灰度比例`只写已确认的互斥对象、比例和灰度。未确认时写对应待确认项；不把“无互斥”当默认值。
- `样本量设置`只能把已经按正式口径验证的结论写成事实。代理事件、近似口径、历史信息或口头确认只能写为待正式复核。
- `来源与附件`逐条保留 owner 提供并用于判断的原始资料。来源必须是可点击的、带可读标题的链接，例如`[价格策略 PRD](https://example.com)`；不得只堆裸 URL。

## 文档排版与视觉规则

- 使用两层结构：文档标题用`#`，十个正式章节用`##`。不要为每一个字段再创建小标题；子项优先用加粗标签、项目符号或表格。
- `待补齐版`仅在文档顶部放一个黄色提示块，说明当前状态和最关键待补项；正式方案不放装饰性状态块。
- 平行信息使用项目符号，一条只表达一个事实或结论。
- 指标、互斥与灰度、分组、样本量等对比字段使用表格；表头使用中性灰色，不使用装饰性配色。
- 定义、限制、代理口径说明等解释性内容使用引用块，不与主要结论混排。
- 正文先呈现事实和结论，来源与补充信息放在对应段落末尾或文末。
- 不使用 emoji、装饰色块、分隔线、营销式空话或大段底层说明。

## 写入或更新文档

所有 Gate 通过后，必须先问 owner：`是否创建飞书文档？` 用户同意后才进入创建或更新路径。Gate9 通过时先写使用日志 `stage_pass`（`stage_code=g9_formal_doc`）。随后完成「是否创建飞书文档？」询问收口后，必须写 `design_end` 且 `--end-status completed`（`stage_code=session_complete`）：owner 回答「否」则立即写入；回答「是」则在创建/更新尝试结果回报后再写入。用户中途结束则写 `--end-status aborted`（`session_abort`），不要写成 complete。口径见 `references/usage-logging.md`。

当用户明确要求创建或更新飞书/Lark 文档，或已明确同意创建飞书文档时：

1. 判断当前是正式方案还是待补齐版，并按上述状态边界准备内容。
2. 除非用户要求直接写入，否则先按默认章节准备内容。
3. 写入或更新成功后，回读验证标题、顶部状态、章节、表格和来源链接，再报告工具返回的文档链接或目标。
4. 写入或更新失败时，报告失败原因；若是目标空间没有写权限，明确请求目标空间最小必要写入授权。未授权时不得默认生成本地 Markdown、XML 或替代文档。
5. 若本次属于 Gate 全过后的正式收口路径，在询问与文档动作完成后写 `design_end --end-status completed`（`result_summary` 简述是否创建及结果）。

不要因为方案成熟就自动创建或更新文档；但一旦用户明确要求，不能以流程未完成为由拒绝创建`待补齐版`。

文档字段写法：

- `评估指标`：固定保留唯一核心指标、过程指标和唯一护栏指标，并只写中文名称、业务可读口径和待确认项；不要写用途、key、事件、字段、映射或确认状态。过程指标和护栏可由 agent 推荐，但均须经 owner 确认后才可作为事实写入。收入类核心指标推荐留存率作为唯一护栏；留存类核心指标推荐收入 ARPU。投诉、退款、负反馈等写风险说明或上线监控。
- `背景必要性`：关键必要性证据用一句话说明它证明的业务问题或机会。
- `实验对象`：只写谁有资格进入实验，不混入场景、文案限制、排除说明、统计单位或分母规则。
- `实验场景`：只写符合对象的用户在什么场景实际触发或看到实验策略；不得重复对象条件，也不得臆造入口、页面、点击或事件。
- `数据支持`：只在 owner 或来源确认已有支持时写已支持；需要新增时列具体新增项；未确认时写`待确认：是否已有场景、对象和指标数据支持`。
- `互斥和灰度比例`：只写已确认的互斥对象、互斥后可用比例和正式灰度比例。没有互斥时，也必须先由 owner 或来源确认后才可写明；仍在样本量测算阶段且尚未选择组合时，写`待根据所需有效流量选择互斥可用比例与正式灰度组合`。
- `具体分组说明`：只写组别、分流比例、用户实际看到的内容；不要另写唯一变量分组字典。默认写到读者可以理解并复核关键差异的层级；若简述不足，补充关键细节、示例或原始配置/价格表等来源链接。
- `样本量设置`：正式结论必须包含计划周期、MDE 及其业务依据、真实目标用户规模、所需有效流量、最终选择的互斥后可用比例、正式灰度比例、组间分流比例、每组有效样本和结论。样本量测算阶段可以先只输出所需有效流量和组合建议。
- `来源与附件`：文末逐条保留 owner 在本次沟通中提供并用于支撑方案判断的 Feishu、PRD、报表、价格表、文件、截图或其他原始资料，填写链接、附件或可访问路径；不按正文是否已引用筛选。

## 读取已有文档

当用户提供飞书/Lark 方案链接并要求评审时：

- 如果已授权且工具可用，使用飞书/Lark 文档工具。
- 把抓取到的文档文本当成方案评审来源。
- 总结时保留文档标题、章节名和重要来源链接。
- 如果文档包含数据说法，表述为 `文档已提供`，不要说成 `已查数`。
- 如果文档说某指标/事件/看板存在，但没有说明是谁确认的，实际支持状态标为 `待确认`。
- 如果文档写了 `只做中英`、文案示例、截图语言、端上先支持或配置项范围，只能当成实现/本地化/配置线索，不能自动写成实验人群限制。实验对象只来自明确的人群、准入、排除、目标用户或 owner 确认。

## 待补齐版规则

- 标题标注`待补齐版`。
- 顶部使用一个黄色提示块，格式为：`状态：待补齐版。当前需优先确认：<最关键缺口>`。
- 每个未确认字段在原章节内标记`待确认：`或`待补充：`，不要把所有缺口堆到文末。
- 过程指标章节始终存在；尚未确认时写`待确认：过程指标及其业务口径`。
- 不展示内部 key、映射、配置或 AI/owner 状态。
- 不要声称实验已经可以配置、上线或得到正式样本量/灰度结论。

## 评审修订循环

当评审目标是解决方案问题，而不是只留下评论时：

1. 先在聊天中按`问题 / 影响 / 建议`评审。
2. owner 接受实质性建议后，再逐项完成方案修订。
3. 最终方案确认后，做一次合并文档更新。评审稿保留原文时，在相关原章节追加`建议更新内容：`；owner 明确要求干净最终版后，才替换评审标记。
4. 写入成功后重新抓取并验证更新内容，只汇报剩余实现或上线缺口。

## 交接边界

如果后续轮次明确使用其他飞书写作或原生排版能力，把已准备内容和已知缺口交接过去。CLI 或原生飞书写作能力只用于文档工作，不得替代 DA/Doris/TA/数据平台验证。
