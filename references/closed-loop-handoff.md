# 闭环交接

当需要在产品规则、AB 设计、数据验证、CMS 配置、上线监控或复盘之间准备明确交接清单时，使用本参考。

路由决策先读取 `capability-routing.md`。本文件只定义需要交接时应交接什么。

## 能力 owner

- `$frank-prd-writer`：当产品规则不清时负责产品规则，包括目标用户、触发、产品行为、频控 / 准入、兜底和验收。
- `$ab-experiment-agent`：负责是否需要 AB、实验设计、指标、分组、风险、样本计划、文档评审 / 修订和交接清单。
- `$da-agents`：负责真实数据验证，包括基线、流量、历史行为、事件可用性、样本量输入、实验中监控和结果读数。
- `$cms`：负责 ABTest 系统和推送系统的 CMS 配置发现与安全操作。默认先只读；没有按 CMS skill 明确确认前，不得写入、发布、启用、停用、回滚、删除或刷新生产配置。

这是能力地图，不是自动生产流水线。每个 skill 都保留自己的安全规则。

## 阶段门槛和交接物

| 阶段 | Owner | 进入下一阶段前需要的输出 |
| --- | --- | --- |
| 产品规则明确 | Frank PRD | 用户、触发场景、策略规则、边界与已知频控 |
| 实验方案确认 | AB | 核心指标、实验对象、被影响用户、分组、策略差异、风险与待确认项；核心指标名不写预估实验天数 |
| 数据可行性确认 | DA | 基线 / 流量 / 事件支持 / 样本输入，以及本次实验观察周期和口径 |
| 上线评审就绪 | AB | 承载系统方向、上线风险、追踪 / 看板计划、自测范围、回滚 owner / 动作、未决阻塞项 |
| 配置就绪 | AB + CMS | 环境、配置路径 / ID 或发现目标、分组值 / 灰度 / 互斥、频控、埋点 / 数据回传、回滚对象、自测计划 |
| 测试验证 | 产品 / 研发 / 运营 | 分组命中、策略展示 / 下发、指标归因、异常与回滚验证记录 |
| 上线监控与复盘 | DA + AB | 核心结果、观察指标、安全监控、累计样本、结论与后续动作 |

## 交接清单

路由给 DA 或 CMS 前，先给一份紧凑交接清单，至少包含：

- 实验名称和本次要做的决策。
- 实验对象、触发场景和分析单元。
- 如果被影响用户不同于实验对象，说明被影响用户和安全风险。
- 对照组和实验组体验，以及唯一预期差异。
- 核心指标、观察指标和安全指标，包括分子、分母和观察窗口。
- 组间比例、实验流量池、互斥关系、周期、样本量 / MDE 状态。
- 必要追踪字段：实验分组、触发、送达 / 曝光、结果事件、来源 / 策略标识。
- 频控、准入排除、停止 / 回滚 owner、未解决事项。

路由给 CMS 时，还要补充目标环境、配置路径 / schema / API 或发现目标、已知前后值、影响范围、生效机制、回滚目标，以及请求是只读、dry-run，还是已明确确认的写操作。

ABTest 系统 CMS 交接补充：服务开关、组值、指标 / 结果回传和组描述。

推送系统 CMS 交接补充：Campaign、Message、目标人群、灰度比例、AB 分组比例、相关时的 `is_plan_to_send` 映射、活动类型、触发条件、进入限制、转化事件、归因窗口、内容差异、追踪字段、频控和暂停 / 回滚动作。

## 上线控制

- 不要只因为实验文档完整就路由到 CMS 写操作。先做只读发现，并在可用时做配置 dry-run。
- 分组分配、触发、实际策略展示 / 下发、结果归因、安全监控和回滚，都能在自测人群中验证后，才能上线。
- 上线前定义监控窗口、异常阈值和谁可以暂停 / 回滚。阈值必须来自适用基线；没有基线时标记 `待确认`，不要复用错误用户角色的基线。
- 实验记录中保留配置快照 / 版本 / ID 和回滚动作。

## 复盘决策

DA 返回结果时，要包含时间范围、人群、组间对比、绝对变化、相对变化、不确定性 / 显著性和数据限制。AB 侧结合样本充分性和安全监控解释结果；不要只因为短期观察指标提升就扩大上线。
