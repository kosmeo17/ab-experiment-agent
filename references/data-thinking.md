# 数据判断

用本参考判断 AB 实验方案是否有足够的数据支持。本文件只是判断框架；本 skill 不直接连接 Doris、TA、DA agents 或其他数据平台。飞书 / Lark 工具只能用于读取或写入方案和来源文档，不能用来验证指标、事件、看板或查询结果。

## 不连接数据平台的边界

允许：

- 询问当前有哪些证据、基线、事件、标签、看板或指标支持。
- 说明数据判断标准。
- 把数据支持标记为 `已确认`、`待确认` 或 `需要新增数据需求`。
- 建议 owner 或数据同学验证某个指标、事件或样本量输入。
- 只有当用户已经提供完整输入时，才使用本地 `scripts/sample_size.py` 做初步样本量计算。

禁止：

- 在用户没有贴出结果时声称已经查过数据。
- 像已经验证过一样生成 SQL。
- 在本 skill 内调用 DA、TA、Doris 或其他数据平台工具。
- 把飞书 / Lark 文档访问当成数据验证。
- 把平台不可用当成方案已经准备好的证明。
- 让用户在本 skill 里调试外部数据连接。

## 证据质量

方案至少包含以下一种具体证据时，实验必要性更强：

- 当前数据：基线率、漏斗流失、流量规模、收入 / 用户行为分布、历史趋势。
- 历史实验或发布结果：过去相关策略曾影响或未能影响相关指标。
- 产品观察：特定场景中可重复的用户行为或运营现象。
- 风险或成本证据：直接上线可能伤害用户、收入、留存、安全或运营负担。

如果没有完整证据但现象具体，先问场景和行为。如果证据和现象都模糊，暂停 AB 路径，先问受影响的用户行为。

## 指标可行性

批准指标前，检查四个问题：

1. 核心指标能否被这次策略直接影响。
2. 核心指标能否在计划实验周期内观察。
3. 分母或分析单元是否清楚。
4. 可能副作用是否有护栏指标。

核心指标和观察指标不能混在一起：

- 核心指标：用于判断实验方向和解释结果的主要指标。
- 观察指标：用于解释漏斗变化和副作用。
- 护栏指标：即使核心指标提升，也可能阻止上线。

收入实验中，除非 owner 明确提供其他业务标准，否则优先使用实验周期内 ARPU 或实验用户人均净收入作为主判断标准。新 SKU 的单项购买率通常只是诊断指标，除非它已经覆盖总增量价值。

## 曝光和触发可行性

触发场景必须说明用户什么时候真正看到或受到策略影响。触发场景模糊时，不批准分组、曝光定义或样本量判断。

在引导和逐步方案生成中，询问当前系统、看板或推送系统是否已经支持已确认的类别：

- 实验场景。
- 实验人群。
- 核心指标。
- 观察指标。
- 护栏指标。

默认问题不要列具体推送或事件字段，例如分组分配、触发事件、送达、点击或聊天窗口跳转。这些细节只在 owner 要求实现交接，或方案进入上线准备检查后才有用。如果任一已确认类别不支持或未知，标记为新增数据需求或配置支持缺口。

## 样本量输入

不要先问灰度比例。先问流量：

- 计划实验人群规模。
- 触发场景 WAU。
- 日曝光。
- 日触发用户。

然后判断核心指标类型：

- 转化率 / 比例。
- 均值 / 用户级人均值。
- ARPU / 收入。
- 次数 / 频次。
- 比率。

只有流量和指标类型清楚后，才问基线、最小有意义提升、组数、组间比例、计划周期，以及必要时的方差 / 标准差。

如果输入缺失，说明缺什么以及为什么重要。不要批准周期或灰度。

## 数据需求输出

使用运营能看懂的表达：

```text
新增数据需求：待确认。当前方案还没说明触发场景是否能被系统识别，也没说明核心指标的分母和统计单位。没有这两项，后续曝光、样本量和复盘口径都会不稳定。
```

如果用户已经贴出足够证据：

```text
新增数据需求：暂未发现必须新增项。已知用户范围、触发场景、核心指标和护栏方向都能被描述清楚；后续仍需要由数据/配置同学确认实际看板或事件是否已覆盖。
```
