# 输出结构

用于判断如何输出评审、生成 AB 实验方案，或准备飞书/Lark 文档内容与内部交接字段。

## 意图到输出形态

| 用户意图 | 输出形态 | 参考材料 |
| --- | --- | --- |
| 评审已有方案 | 先给结论，再给阻塞点、下一步，必要时给维度表 | `assets/review-report-template.md` |
| 引导不完整想法 | 默认只问下一个问题；不输出评审结论或长推理 | `references/question-bank.md` |
| 生成 AB 方案 | 先问下一个缺失硬门槛；可生成待补齐版 | `assets/ab-plan-template.md` |
| 准备或写入飞书/Lark 文档 | 用户明确要求时创建/更新；字段不全则生成待补齐版 | 本文件和 `references/feishu-export.md` |

运营只需要下一步时，不要输出完整评审报告。普通运营草稿不要展示承载系统、实现方式、配置路径或待研发确认等内部交接信息，除非它会改变实验对象、分组逻辑、触发定义或指标归因。

用户明确要求创建或更新飞书文档时，`ready_to_plan_doc`不是写入许可：字段不全也要创建或更新`待补齐版`。它只表示是否可以把文档称为`正式方案`。飞书正文格式与视觉规则以`references/feishu-export.md`为准。

## AB 方案生成输出

业务文档使用以下十个章节：

1. 背景与必要性
2. 评估指标
3. 实验对象
4. 实验场景
5. 数据支持
6. 互斥和灰度比例
7. 具体分组说明
8. 样本量设置
9. 上线前检查、实验过程中的复盘与提醒
10. 来源与附件

硬规则：

- 缺失事实必须写`待确认：`或`待补充：`，不得编造、不得默认写`无`。
- `评估指标`固定包含核心指标、过程指标和护栏指标。过程指标可由 agent 推荐，但每一项需要 owner 确认；未确认时保留待确认项，不得省略该章节或默认写无。
- 护栏只允许一项。agent 可按核心指标类型推荐，但必须由 owner 确认后才可作为事实写入。
- 内部标准库映射、key、字段/事件、映射状态、确认状态、AI 状态和配置细节，不得出现在业务飞书文档或普通运营方案。
- 正式方案必须通过内部`陌生读者无疑问`自检，但不把自检过程写进业务正文。
- owner 提供并用于判断的 Feishu、PRD、报表、价格表、文件或其他原始证据，必须在文末`来源与附件`完整保留。来源使用带可读标题的可点击链接，不堆裸 URL。

正式方案边界：必要性、指标确认、对象、场景、数据支持、分组、互斥、样本量与灰度证据均已闭合时，才可称正式方案。未闭合时可写`待补齐版`，但不得写成已验证、已定稿或可进入配置准备。

## 内部结构化字段

这些字段用于 agent 判断、数据验证和配置交接；不是业务飞书正文的字段清单。

### 基础信息

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| experiment_name | 是 | 人能读懂的实验名称。 |
| owner | 否 | 用户提供则保留。 |
| business_line | 否 | 用户提供则保留。 |
| business_domain | 是 | 业务域；上下文推断时内部标记为 AI 推断。 |
| source_links | 条件必需 | 本次沟通中用于判断的原始资料。 |
| status | 是 | `idea`、`reviewing`、`ready_to_plan_doc`、`data_feasibility_needed`、`ready_for_launch_review`、`ready_to_config`、`ready_to_launch`。 |

状态边界：

- `idea` / `reviewing`：方案仍在澄清。
- `ready_to_plan_doc`：可以称为正式方案；设计与证据字段足以支持当前决策。它不是创建待补齐版飞书文档的前提。
- `data_feasibility_needed`：设计足以定义数据问题，但事件、基线、流量、样本输入、监控或读数需要数据验证。
- `ready_for_launch_review`：可以进入上线前评审；不等于已配置或已上线。
- `ready_to_config`：在`ready_to_plan_doc`基础上，承载系统、配置入口、配置方法、负责人和安全细节已足够明确。
- `ready_to_launch`：配置、自测、追踪、数据回传、监控与回滚均由负责人确认。

这些状态是内部状态。业务文档只展示与证据相称的结论或待确认项。

状态表述必须和证据口径一致。若基线、流量或样本量使用的是代理事件、近似分母、历史替代窗口、未核验看板、PRD 截图或 owner 口头确认，顶部状态只能写 `基于代理口径估算`、`待正式事件复核` 或 `待上线前校验`。只有按正式实验分母/分子/事件和计算输入完成验证，才能写 `已验证`、`已定稿` 或 `可进入配置准备`。

### 实验必要性

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| proposed_strategy | 是 | owner 想做什么。 |
| problem_or_opportunity | 是 | 现象、数据、用户问题或业务问题。 |
| business_goal | 是 | 服务什么业务目标。 |
| causal_hypothesis | 是 | 为什么策略可能解决问题。 |
| why_ab | 是 | 为什么需要 AB，而不是直接上线、直接修复或暂时不做。 |
| necessity_evidence | 条件必需 | 正文说明其支持的判断；原始资料保留在来源与附件。 |

### 指标

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| core_metric | 是 | 唯一主要成功标准。 |
| core_metric_standard_name | 是 | 中文标准指标名称。 |
| core_metric_key | 是 | 内部系统标识；不得渲染到业务飞书文档或普通运营方案。 |
| core_metric_mapping_status | 是 | 内部记录：已映射标准库 / 需新增标准指标。 |
| core_metric_confirmation_status | 是 | 内部记录：owner 已确认 / AI 推荐待确认 / 待补充。 |
| core_metric_type | 是 | conversion / mean / arpu / count / ratio / other。 |
| process_metrics | 是 | 固定章节。每项记录中文名称、简短业务口径和 owner 确认状态；agent 可推荐，未确认不得当作事实或默认无。 |
| guardrail_metric | 是 | 唯一护栏指标。 |
| guardrail_metric_key | 是 | 内部系统标识；不得渲染到业务飞书文档或普通运营方案。 |
| guardrail_confirmation_status | 是 | owner 确认前只能作为推荐或待确认项。 |
| risk_notes | 否 | 投诉、退款、负反馈等风险说明或上线监控，不作为实验指标。 |

收入、付费、价格、SKU、折扣、Paywall 类核心指标，agent 推荐留存率作为唯一护栏；留存、活跃、互动、召回类核心指标，agent 推荐收入 ARPU。无论推荐结果如何，最终都由 owner 确认。

### 对象、场景与数据支持

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| experiment_object | 是 | 只写谁有资格进入随机分组。 |
| trigger_scene | 是 | 只写这些用户何时、何处实际受到策略影响。 |
| exposure_unit | 否 | 内部校验字段，普通业务文档不展示。 |
| new_data_support_status | 是 | 已确认支持 / 需新增 / 待确认。未确认时不能默认断言无需新增。 |
| missing_new_data_requirements | 条件必需 | 需要新增时列出具体新增项。 |

### 分组与互斥

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| group_count | 是 | 组数。 |
| group_ratio | 是 | 组间分配比例。 |
| group_user_experience | 是 | 每组用户实际看到的内容。 |
| core_comparison_variable | 是 | 内部校验字段，业务正文不另设“唯一变量”章节。 |
| group_stranger_self_check | 是 | 内部 P0 自检；不通过时不能称正式方案。 |
| mutual_exclusion_status | 是 | 已确认有互斥 / 已确认无互斥 / 待确认。不得把无互斥当默认值。 |
| mutex_scope | 条件必需 | 已知时记录互斥对象和范围。 |
| required_effective_traffic | 条件必需 | 样本量阶段反推的所需有效流量。 |
| final_mutex_gray_combination | 正式方案必需 | owner 确认的最终互斥与灰度组合。 |

### 样本量与上线

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| first_week_wau | 样本量阶段必需 | 公司 notebook 口径的实验场景首周 WAU。 |
| metric_baseline_14d | 样本量阶段必需 | 核心指标过去 14 天初始值。 |
| mde_type_and_value | 样本量阶段必需 | 相对或绝对提升及业务依据。 |
| sample_size_source | 样本量阶段必需 | 公司 notebook / 公司计算器 / 数据 BP / 粗估 / 待确认。 |
| sample_size_result | 条件必需 | 正式口径结果，或明确待确认。 |
| planned_duration | 样本量阶段必需 | 计划实验周期。 |
| launch_readiness | 上线准备必需 | 配置、看板、自测、回传、监控和回滚准备。 |

代理事件、近似分母、历史替代窗口、未核验看板或口头确认只能作为待正式复核，不能支撑`已验证`、`已定稿`或`可进入配置准备`。

### 配置交接

配置交接只在用户明确要求配置或上线准备时使用。服务开关、组值、Campaign、Message、`is_plan_to_send`、配置路径、负责人、频控和回滚等属于内部/CMS 交接，不写进普通运营方案或业务飞书正文。

正式方案或飞书文档完成后，追加简短提醒：如果方案确认无误，可以继续整理实验配置上线清单；进入配置前需要用户再次确认实验配置中双端测试是否已经通过。实验跑完后，可以用 `$da-agents` 辅助复盘。不要把这写成已经自动监控或已经配置。

## 面向运营的表达

告诉 owner 当前唯一下一步。证据不足时说明判断标准，不展示内部 Gate、key、SQL、日志或配置字段。正式方案完成后可提示进入配置上线清单；这不表示已自动配置或上线。
